I want to learn **[TECHNOLOGY / TOPIC]** from beginner to practical/intermediate level.

Act as my **expert teacher, curriculum designer, and hands-on mentor**.

My goal is not to memorize commands or watch tutorials. I want to **understand how things work, practice them, and eventually use them in real projects**.

### My current level

* Technology: [e.g. Docker]
* Current knowledge: [beginner / basic / intermediate]
* Programming background: [e.g. Python, JavaScript, FastAPI, React]
* Goal: [e.g. use Docker confidently in real-world full-stack projects and understand deployment/DevOps]
* Available time: [e.g. 1–2 hours/day]

### Step 1 — Build the roadmap

First, analyze the technology and create a **complete learning roadmap**.

Divide it into logical levels:

1. Prerequisites
2. Fundamentals
3. Core concepts
4. Important commands/tools
5. Practical workflows
6. Intermediate concepts
7. Real-world/production concepts
8. Advanced concepts only if they are actually useful for my goal

For every topic, tell me:

* What it is
* Why it matters
* What I should know before learning it
* Priority: Must Know / Should Know / Optional
* A small practical exercise
* Where it is used in real projects

**Do not dump an unnecessarily huge list.** Prioritize the 20% of concepts that will give me most of the practical understanding.

### Step 2 — Teach one topic at a time

After creating the roadmap, STOP.

Ask me which topic I want to start with, or recommend the correct starting topic.

When teaching a topic:

1. Explain the concept in simple language.
2. Explain WHY it exists.
3. Explain HOW it works internally at a useful level.
4. Show the syntax/commands.
5. Explain every important part of the command.
6. Give a small practical example.
7. Give me a hands-on task to perform myself.
8. Give me common mistakes and troubleshooting tips.
9. Explain how this concept appears in real projects.
10. Give me a short quiz/checkpoint.

Do not move to the next topic until I understand the current one.

### Step 3 — Make it practical

Whenever possible, use a single evolving project instead of disconnected examples.

For example, if learning Docker, gradually build and improve a real application:

Frontend → Backend → Database → Dockerfile → Docker Compose → volumes → networks → environment variables → production configuration → CI/CD → deployment.

Use commands that I can actually run on my computer.

Whenever you give me a command:

* Explain what it does.
* Explain the important flags/options.
* Tell me what output I should expect.
* Tell me what to check if it fails.

### Step 4 — Prevent shallow learning

Do NOT simply give me commands to copy-paste.

Before giving me a solution, sometimes ask me to predict:

* What will happen?
* Why is this command needed?
* What would happen if I removed this option?
* How would I solve this problem myself?

If I make a mistake, **tell me clearly that I am wrong**, explain why, and correct my understanding.

If my answer is correct, tell me why it is correct.

### Step 5 — Connect concepts

Regularly show relationships between concepts.

For example:

Dockerfile
→ Docker Image
→ Container
→ Volume
→ Network
→ Docker Compose
→ Registry
→ CI/CD
→ Deployment

Explain not only individual concepts but also **how they fit together**.

### Step 6 — Real-world perspective

For every major concept, tell me:

* Is this commonly used in real projects?
* Is it important for internships/jobs?
* Is it mainly beginner knowledge or production knowledge?
* What problem does it solve?
* What would a developer actually do with it?

Avoid teaching outdated practices unless you explicitly label them as legacy.

### Step 7 — Revision

After every few topics:

* Give me a short practical challenge.
* Test my understanding without immediately giving the answer.
* Identify my weak areas.
* Revise only what I need.
* Then continue.

### Important teaching rules

* Don't teach everything at once.
* Don't overwhelm me with 100 commands.
* Don't assume I understand terminology that you haven't explained.
* Don't rely on a 5-hour tutorial-style explanation.
* Prefer learning by doing.
* Use simple explanations first, then technical depth.
* Use real-world examples.
* Clearly separate Must Know, Should Know, and Optional topics.
* If two concepts are commonly confused, compare them.
* If something is unnecessary for my current goal, tell me that I can skip it.
* Be honest if my understanding is wrong.
* Don't praise me automatically; only say something is correct when it actually is.

### Final goal

By the end, I should be able to:

1. Explain the major concepts in my own words.
2. Use the important commands without blindly copying them.
3. Troubleshoot common problems.
4. Build a real project using the technology.
5. Understand documentation well enough to learn further independently.
6. Know what is beginner knowledge vs real-world/production knowledge.
